# Product Requirements Document (PRD): Life Insurance Module

## 1. Project Objective

Implement a fully integrated Life Insurance tracking and management module within the existing Single Page Application (SPA) client portal. This module allows the Admin to perform comprehensive CRUD (Create, Read, Update, Delete) operations via a detailed Policy Entry form, while restricting Clients to a secure, read-only dashboard. Additionally, the module features a frontend-generated PDF export tool that produces a formatted "Comprehensive Insurance Chart" for the user.

## 2. Architecture & File Constraints

* **Single Page Application (SPA):** All logic, styling, and markup must be embedded within the existing `portal.html`, `portal.css`, and `portal.js` structure. No new HTML pages will be created.
* **DOM Manipulation:** Navigation between the dashboard list view and the detailed Admin form will be handled via standard JavaScript display toggles (e.g., swapping `display: none` and `display: block`).
* **Client-Side PDF Generation:** The PDF export must be executed entirely on the frontend using libraries such as `jsPDF` and `jspdf-autotable` to parse the JSON state and render the chart without backend processing.
* **Data Separation:** Life Insurance Sum Assured values must be kept strictly separate from the General/Health "Total Family Aggregate Sum Insured" displayed on the portal's main Home tab.

## 3. Access & Permission Matrix

| Feature | Admin Role | Client Role (POC / Profile) |
| --- | --- | --- |
| **View Policy Dashboard (Cards)** | Full Access | Full Access |
| **Interactive Policy Links** | Yes (Opens Policy Entry form) | No (Disabled / Read-only text) |
| **Policy Entry Form (CRUD)** | Full Access | Denied / Hidden |
| **View/Edit Nominee Details** | Full Edit Access | Read-Only View |
| **Export PDF Chart** | Full Access | Full Access |

## 4. Admin Interface: Policy Entry Form (CRUD)

Clicking the hyperlinked Policy Number on a dashboard card opens the Policy Entry interface. The form is structured into the following distinct sections:

### 4.1 Action Bar

* Features a "Save" button, "Update" button, and a "Back/Exit" arrow to return to the list view.



### 4.2 Policy Holder's Details

* Contains Group Name (Text), Group Code (Text), Life Assured (Dropdown), Date of Birth (Date Input), Age at NBD (Number), Gender (Dropdown), and a PAN Registered checkbox.


* *Validation:* The "PAN Registered" checkbox acts purely as a visual UI flag; strict regex validation for a PAN format is not required.

### 4.3 Policy Details

* Captures Policy Number, Commencement Date (Date Input), Completion Date (Read-only Date), Plan Name/Number (Text/Dropdown), Mode (Dropdown), Term (Number), PPT (Number), Extra Class (Dropdown), and Rate (Percentage).


* *Automation Logic:* `Completion Date` must automatically calculate by adding the `Term` (in years) to the `Commencement Date`.

### 4.4 Policy Premium Calculation

* A synchronized calculation block capturing Sum Assured, Basic Yearly Premium, Total Rider Premium (auto-summed from the Riders section), Installment Premium, GST, and Total Installment Premium.



### 4.5 Riders Details

* A tabular section allowing the Admin to toggle specific riders (e.g., Double Accident Benefit) via checkbox and define their Sum, Term, PPT, and Premium.



### 4.6 Nominee Details (New)

* A dedicated form block allowing the Admin to input "Nominee Type" (Dropdown), "Nominee Name" (Text Input), and "Relationship with Policy Holder" (Dropdown/Text Input).

## 5. Client Interface: Dashboard & PDF Export

### 5.1 Read-Only Dashboard

Clients and Admins share the primary dashboard view, consisting of data cards.

* **Card Data Points:** Insurer Badge (e.g., LIC), Policyholder Name, Plan Name/Number, Mode, Term, Sum Assured, Group Code, GST, FUP Date, PPT, Commencement Date, and Premium Amount.


* **Client Restrictions:** The Policy Number is rendered as standard text for Clients; it does not trigger the CRUD interface. Nominee Details will be visible within an expanded view of the card.

### 5.2 Comprehensive Insurance Chart (Frontend PDF Export)

A prominent "Export PDF" button on the dashboard triggers the frontend script to generate a tabular report mimicking the physical chart.

* **Header Section:** Displays the Agent's contact details (Top Left), Document Title ("Comprehensive Insurance Chart"), and "As on [Current Date]" (Top Right).


* **Account Meta Data:** Centered display of the primary POC's Name, Group Code (e.g., `[ Z003 ]`), Full Address, and Contact Numbers.


* **Data Structure:** The table rows are grouped dynamically by the "Life Assured" field, creating sub-headers for each family member (e.g., "Mr. RAJESH N. ZATAKIA").


* **Table Columns:**
1. Sr. No


2. Policy No.


3. Com. Date


4. Pl/Tm/PT (Combined string: Plan/Term/PPT)


5. Plan Name


6. Sum Assured


7. Premium


8. Md (Mode)


9. Nominee (Pulled from the Nominee Details section)
10. Accidental Riskcover (Mapped from Riders Details)

* **Rider Parsing Logic:** If a policy has multiple active riders, the PDF generation script must list each rider on a separate row beneath the primary policy entry within the chart.
