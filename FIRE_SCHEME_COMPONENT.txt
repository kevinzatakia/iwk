# System Prompt / PRD: Fire & Property Insurance Progressive Form with Email Capture

## 1. Project Objective
Build an interactive, step-by-step Fire & Property insurance lead capture flow for a vanilla HTML/CSS/JS single-page website. The form must use progressive disclosure—each question/component is revealed only after the previous one is successfully answered. 
It includes a dynamic sum-insured calculator. Upon completion, the form must gather all data into a JSON payload and send it directly to the site owner's email address using the EmailJS library.

## 2. Tech Stack Constraints
* Frontend: Vanilla HTML5, CSS3, and Vanilla JavaScript (ES6+).
* Styling: Custom CSS (Flexbox/Grid). DO NOT use Tailwind, Bootstrap, or external CSS frameworks. Use smooth CSS transitions (`opacity`, `transform`, `max-height`) for revealing new steps.
* Email Delivery: Integrate the EmailJS SDK (`https://cdn.jsdelivr.net/npm/@emailjs/browser@4/dist/email.min.js`).
* Architecture: Output the final code as a single block (HTML with embedded `<style>` and `<script>` tags).

## 3. UI/UX Specifications & Progressive Flow
* Container: A clean, centered card UI with a maximum width of `600px` (slightly wider to accommodate the asset table).
* Transitions: When a user completes a step and clicks "Next", lock the input, show a brief success state/summary, and slide down the next question.
* Layout: Previous answers remain visible but in a minimized/read-only state.

## 4. State Machine & Component Sequence
Implement the following exact sequence using DOM manipulation. Store data in a `formData` object.

### Step 1: Base Contact Details
* UI: Standard input fields for Name (Text), Phone Number (Tel), and Email (Email).
* Interaction: A "Next" button. Validate fields before advancing.

### Step 2: Risk Location
* UI: 
  - Textarea for "Risk Location Address".
  - Text input (Number/Tel) for "Pincode".
* Interaction: A "Next" button.

### Step 3: Nature of Occupancy
* UI: A large text input or textarea titled "What is the primary nature of occupancy or business activity at this location?"
* Subtext UI: Add muted/smaller helper text below the input: *"Occupancy refers to how the premises are used or what is stored there (e.g., Residential Building, Steel Manufacturing Factory, Warehouse)."*
* Interaction: A "Next" button.

### Step 4: Asset Description & Sum Insured (The Calculator)
* UI: A clean, two-column CSS Grid or HTML Table layout. Column 1: Asset Label. Column 2: Integer Input (prefixed with ₹).
* Fields required:
  1. Building including plinth, Basement and additional structures
  2. Furniture & Fixtures, Fittings and other equipment
  3. Plant & Machinery
  4. Other Contents
  5. Raw Material
  6. Stocks in process
  7. Finished Stock
  8. Stocks Held in Trust
* Dynamic Logic: At the bottom of the list, display a bold "Total Sum Insured: ₹0". Attach an `input` event listener to all asset fields so that whenever a user types a number, the Total Sum Insured updates in real-time. (Ensure empty fields are treated as 0).
* Interaction: A "Next" button.

### Step 5: Hypothecation (Bank Finance)
* UI: Radio buttons styled as large clickable pills. Options: "Yes", "No".
* Logic: 
  - If "Yes" is selected, dynamically slide in a text input asking "Name of the Financier (Bank/Institution):".
* Interaction: A "Next" button (or auto-advance if "No" is selected).

### Step 6: Additional Risk Details
* UI: A textarea labeled "Anything specific I need to know regarding the risk or the risk location?"
* Interaction: A final "Submit for Quote" button.

## 5. EmailJS Implementation Instructions
1. Include the EmailJS script in the `<head>`.
2. On final submit, prevent default form behavior. Change the Submit button text to "Sending...".
3. Format the collected `formData` object (including the calculated Total Sum Insured) into a clean, readable string.
4. Call `emailjs.send("YOUR_SERVICE_ID", "YOUR_TEMPLATE_ID", { message: formattedData, reply_to: formData.email, from_name: formData.name })`.
5. Add explicit comments in the code showing exactly where the developer needs to insert their EmailJS Public Key, Service ID, and Template ID.
6. On success promise resolution, hide the form and display a "Success! Your property details have been submitted for review." message.
