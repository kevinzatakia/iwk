# Product Requirements Document (PRD): Admin Panel Updates & Notification System

## 1. Project Objective

Enhance the admin portal to streamline document management, grant the admin full control over the policy lifecycle, manually track aggregate and individual coverage values, and automate critical user communications via the existing Google Apps Script (GAS) infrastructure.

## 2. System Architecture: Account vs. Profile Hierarchy

To ensure correct routing of policies and notifications, the system enforces the following hierarchy:

* **Account (POC):** The primary Point of Contact and app holder. All push notifications (renewals, new policies) are routed exclusively to the Account. Policies can be directly attached here.
* **Profile:** Dependents or family members mapped *under* an Account. Policies can be attached to specific profiles for organizational clarity. Profiles do not receive notifications; their alerts route to the parent Account.

## 3. Feature Specifications

### 3.1 Multi-File & Drag-and-Drop Upload

* **Module:** "Send a Policy" and all other admin document upload interfaces.
* **UI/UX Requirements:**
* Implement a primary drag-and-drop zone with visual feedback (e.g., background color change on hover).
* Include a standard "Browse Files" button within the zone.
* Allow multi-file selection natively from the OS file browser.
* **Staging Area:** Display a list of selected files with a "Remove" (X) button before the admin clicks "Upload/Send".


* **Constraints:** As this is an internal admin tool, there are no strict file size, type, or quantity limits enforced by the frontend.

### 3.2 Policy Management: Expiry Tracking & Deletion

* **Expiry Date Picker:**
* During the "Send a Policy" upload flow, require the admin to select an "Expiry Date" via a calendar input for each policy.
* The Admin's "View Policies" dashboard must display this date clearly.


* **Delete Capability (Soft Delete):**
* In the Admin's "View Policies" dashboard, add a "Delete" (trash icon) button next to each policy.
* **Interaction:** Clicking Delete triggers a confirmation modal: *"Are you sure you want to remove this policy document from the user's view?"*
* **Action:** The system deletes the database link connecting the policy to the Account/Profile, removing it entirely from the user-facing app. The physical file remains untouched in the backend storage bucket.



### 3.3 "Sum Insured" Data Field Integration

* **Modules:** Account Creation, Profile Creation, and Edit screens.
* **Data Structure:** A manual currency/number field labeled "Sum Insured".
* **Admin Logic:** The admin manually inputs the specific sum insured for the main Account (POC) and separately for each individual Profile. The admin can overwrite these values later as policies change.
* **Frontend Visibility (Family Mode):**
* The POC's main app dashboard must calculate and display a "Total Family Aggregate Sum Insured" (the sum of the POC's SI and all dependent Profiles' SIs).
* Within the UI, this breaks down individually, clearly displaying the POC's personal Sum Insured next to their name, and each dependent's specific Sum Insured next to their respective Profile card.



### 3.4 Automated & Triggered Push Notifications (GAS Integration)

Utilize the existing Google Apps Script (GAS) notification infrastructure to push alerts directly to the **Account (POC)**.

* **Trigger 1: Policy Dispatch (Manual Admin Action)**
* *Event:* Admin successfully uploads and sends a policy to an Account or Profile.
* *Action:* Trigger GAS endpoint to send a push notification to the POC.
* *Dynamic Content:* If the policy is for the POC: *"Your new policy document has been uploaded."* If for a Profile: *"[Profile Name]'s new policy document has been uploaded."*


* **Trigger 2: 30-Day Renewal Alert (Automated Cron Job)**
* *Event:* A daily GAS trigger runs at a set time (e.g., 08:00 AM) checking all policy Expiry Dates in the database.
* *Condition:* `ExpiryDate - 30 days == Current Date`.
* *Action:* Trigger push notification to the associated POC.
* *Dynamic Content:* *"Renewal Reminder: [Profile Name/Your] policy expires in 30 days. Please contact Kevin for renewal."*
