# Product Requirements Document (PRD): Insurance Modifiers Implementation

**Project:** Insure It With Kevin - Premium Calculator Update
**Objective:** Update the frontend vanilla JS wizard (`health.js`) to capture inputs required for discounts/loadings and calculate the final New India Assurance (NIA) Yuva Bharat premium accurately using the updated JSON database.

## 1. Current State vs. Required State

### Current State:

* `health.js` captures: Name, Email, Phone, Age, Members, Zone, Intent, Sum Insured, and Pre-existing conditions.


* The calculation logic in `calculateFinalPremium()` only matches `planType`, `zone`, `sumInsured`, and `age` to pull the `basePremium`. It ignores Floater Discounts, Maternity Add-ons, Loyalty, Long-term discounts, and specific health metric adjustments.



### Required State:

* The wizard must capture additional UI states (Maternity, Term length, Loyalty, specific BMI/Hb1Ac/BP metrics).
* The `calculateFinalPremium()` function must apply the `modifiers` and `optionalCovers` from the JSON database sequentially before calculating the 18% GST.


---

## 2. Required UI Changes (`compare.html` & `health.js` View Layer)

To apply the modifiers, we need to gather new data from the user. The progressive wizard (`ybWizard`) must be expanded.

### Step Addition / Modification:

1. **Modify Step 7 (Conditions):** Currently, it just asks for "Diabetes, Hypertension, Asthma...". We need to capture the *severity* or metrics for the Health Parameters discount/loading logic.


* **New Action:** If "Diabetes" is checked, reveal a sub-question: *"Is your Hb1Ac > 6.4?" (Yes/No)* to determine if the 2.5% loading or discount applies.


* **New Action:** If "Hypertension" is checked, reveal a sub-question: *"Is your BP > 139/89?" (Yes/No)*.


* **New Action:** Add a general question: *"Have you been hospitalized in the last 3 years?" (Yes/No)* to determine the 2.5% discount.


2. **New Step: Health Metrics (Step 7.5):**
* Ask for Height and Weight to calculate BMI internally.
* If BMI >= 18.5 and < 32, apply `-0.025`. If BMI > 32, apply `0.025`.


3. **New Step: Policy Details (Step 8):**
* *Question 1:* "Do you want to buy this policy for 1 year, 2 years, or 3 years?" (Maps to `longTermDiscount` of 0%, 5%, or 7%).


* *Question 2:* "Do you have an existing retail policy with New India Assurance?" (Yes/No) (Maps to `loyaltyDiscount` of 2.5%).


* *Question 3:* (Only show if `planType` is Platinum and a female is covered): "Do you want to add Enhanced Maternity cover?" (Maps to `optionalCovers.enhancedMaternity`).


Note: Since the JS relies on DOM elements existing (e.g., `document.getElementById('ybStep8')`), the `compare.html` file must have new `<div class="yb-step hidden">` blocks added to accommodate these new steps.

## 3. Required Logic Changes (`health.js` Controller Layer)

The `formData` object and the `calculateFinalPremium` function in `health.js` must be rewritten.

### 3.1 Data State Modification

Update the global `formData` object to include the new keys:

```javascript
var formData = {
  // ... existing fields[cite: 3] ...
  policyTermYears: 1, // 1, 2, or 3
  hasExistingNiaPolicy: false,
  wantsMaternity: false,
  maternityLimit: null, // 50000, 75000, 100000
  bmi: null,
  healthMetrics: {
    isDiabeticOverLimit: false, // Hb1Ac > 6.4
    isHypertensiveOverLimit: false, // BP > 139/89
    hospitalizedLast3Years: false
  }
};

```

### 3.2 Calculation Rewrite

Replace the existing `calculateFinalPremium` function with the sequential math logic required by the new JSON schema.

The new function must execute in this strict order:

1. **Base Premium Lookup:** Use the existing `.find()` logic to get the base rate.

2. **Optional Covers:** If `formData.wantsMaternity` is true, add the corresponding `annualPremium` from `optionalCovers.enhancedMaternity` based on the user's zone and chosen limit.

3. **Floater Discount:** Calculate `formData.members.length`. If it's a family floater, apply the discount from `modifiers.floaterDiscount` based on the member count (capped at 4).

4. **Health Parameters (Age 18+ only):**
* Evaluate `formData.bmi` and `formData.healthMetrics` against the percentages in `modifiers.healthParameters`. Sum all applicable percentages (discounts are negative, loadings are positive) and multiply by the running premium total.

5. **Loyalty & Long Term:** Subtract `modifiers.loyaltyDiscount` (2.5%) if `hasExistingNiaPolicy` is true. Subtract `modifiers.longTermDiscount` based on `formData.policyTermYears`.

6. **GST Calculation:** Finally, take the resulting sum and multiply by `metadata.taxRateGST` (0.18) to get the final total.

### 3.3 Output Formatting

Update the `renderNiaEstimate` function so it no longer just outputs `out.premium`. It must destructure the new return object and format it into Indian Rupees using the `inr()` helper function:

```javascript
// Inside renderNiaEstimate:
row('Base Premium (inc. Add-ons)', inr(out.basePremium));
row('Discounts & Loadings Applied', inr(out.finalBeforeTax - out.basePremium));
row('GST (18%)', inr(out.gstAmount));
row('Total Estimated Premium', inr(out.totalPremium), 'calc-total');

```
