## **Revised PRD Section: Multi-Member Health Metrics & Modifiers**

### **1. Feature Overview**

The Yuva Bharat policy applies health-based premium discounts and loadings on an individual basis, rather than a flat policy level. Therefore, the frontend wizard cannot assume a single health profile for a Family Floater plan. The UI must dynamically generate health metric questions for multiple members when applicable, calculate their individual modifiers, and aggregate them.

### **2. Trigger Requirements for Health Questions**

The UI must **not** ask health metric questions for every person indiscriminately. The appearance of the Health Metrics UI (Step 7.5) is strictly gated by the following logic:

* **Age Trigger:** Health parameter discounts and loadings apply *only* to members who are 18 years of age and older.
* **Data Source Check:** When the user transitions from Step 7 to Step 7.5, the system must loop through the `formData.members` array and check the corresponding age in the `formData.ages` object.
* **Minor Exclusion:** Any member whose logged age is < 18 must be completely skipped and hidden from Step 7.5.
* **Condition Check (Optional but Recommended):** To reduce friction, the detailed metric questions (like Hb1Ac or BP) can be triggered to appear *only* if the user selected the corresponding broad condition (Diabetes or Hypertension) in Step 7.

### **3. UI Rendering Requirements (Step 7.5: Health Metrics)**

If the age trigger is met, the UI must render a distinct question block for **each qualifying adult**.

**For each member where `age >= 18`:**

1. **Display Member Header:** Clearly identify who the questions belong to (e.g., "Health Details for Spouse (Age: 38)").
2. **BMI Inputs:** Render two number inputs for `Height (cm)` and `Weight (kg)` to calculate BMI internally.
3. **Medical Metric Toggles (Yes/No Buttons or Checkboxes):**
* *Diabetes:* "Is their Hb1Ac level > 6.4?"
* *Hypertension:* "Is their Blood Pressure > 139/89?"
* *Hospitalization:* "Have they been hospitalized for more than 24 hours in the last 3 years?"

### **4. Controller Logic Updates (`health.js`)**

The `formData` object must be restructured to group health metrics by member name, rather than using a flat array.

* **New Data Structure:**
```javascript
formData.healthMetrics = {
  "Self": { bmi: null, isDiabeticOverLimit: false, isHypertensiveOverLimit: false, hospitalizedLast3Years: false },
  "Spouse": { bmi: null, isDiabeticOverLimit: false, isHypertensiveOverLimit: false, hospitalizedLast3Years: false }
  // Minors like "Son 1" are excluded from this object.
};

```

* **Modifier Math Calculation:**
During `calculateFinalPremium()`, the Javascript must:
1. Loop through all keys in `formData.healthMetrics`.
2. Evaluate each adult's metrics against the `modifiers.healthParameters` values in the JSON database (-0.025 for healthy, +0.025 for adverse).
3. Sum the percentages of *all* adults combined.
4. Apply this master aggregated percentage to the base premium.
